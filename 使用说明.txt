知乎前 X 条回答导出长图（桌面 Chrome / Edge / Firefox + Tampermonkey）

作者：jasonLi。当前版本1.8.0，同时提供Chrome / Edge扩展。完整安装和发布方法见README.md及PUBLISHING.md。

进度：按收集回答、加载图片、生成文件显示实际数量、阶段进度和累计耗时；无法准确计量时显示“处理中”。完成后显示文件总大小。收起的小按钮也显示当前阶段。

安装更新：用浏览器打开docs/install.html，或从扩展弹窗打开“安装与更新指南”。发布到GitHub并打版本标签后，工作流自动绑定真实仓库，生成油猴自动更新地址和稳定下载包。扩展开发者模式更新仍需覆盖原目录、重新加载；详细步骤见PUBLISHING.md。当前本地包未绑定仓库，不能在首次Release发布前宣称在线自动更新已生效。

PNG加速：减少重复截图和像素复制，改为批量读取；较短图片使用浏览器原生编码，可能生成更大的文件。需要优先压缩体积时，CONFIG中把PNG_FAST_MAX_PIXELS设为0；超长流式PNG仍享受批处理加速，保持像素和分辨率。

面板右上角“×”可收起到右下角小按钮，点击“长图工具”重新展开；状态会记住。收起不中断导出，任务期间小按钮显示“导出中…”。

PDF图片不跨页：在格式下拉框选择PDF后显示复选框，默认开启且自动记住。图片放不下时整体移到下一页；超高图片等比缩小到一页内，可能产生页底留白。关闭则恢复固定高度分页。文字和图片说明仍可能跨页。

1.8.0设置自动记忆：修改右下角的回答数量、清晰度和导出格式后立即保存，不必先导出。刷新、切换问题或重启浏览器会恢复。油猴和扩展分别保存在各自的本地存储，不自动跨设备同步。已保存值优先于CONFIG默认值。

1. 在油猴管理面板点击“添加新脚本”，删除默认内容，粘贴 zhihu-long-image.user.js 的全部内容并保存。
2. 在 CONFIG 中把 ANSWER_COUNT: 10 改成需要的数量，例如 ANSWER_COUNT: 5。
   也可以直接使用页面面板的“回答数”和“清晰度”控件。
3. 打开 https://www.zhihu.com/question/2087509207285248045 或其他知乎提问页面。
4. 登录并选择需要的回答排序（默认排序、时间排序等），建议先刷新页面，让回答列表从顶部开始加载。
5. 点击右下角“单张高清长图”。期间不要切换排序、滚动操作或离开当前页面。
6. 完成后在预览窗口点击“下载 PNG 长图”。

选择导出格式（1.8.0）
- 在右下角按钮下面的“导出格式”下拉框选择PNG、SVG、HTML、PDF或WebP，再导出。
- 批量导出和“导出此回答”均使用所选格式。
- SVG/HTML保留真实文字和内嵌照片，不使用清晰度倍率；SVG推荐浏览器打开。
- PDF为高清截图分页文档，文字不可选择。
- WebP为95%有损质量，超长时请高清分图；单张超过编码器上限会提示，不自动缩小。
- 1.8.0超长WebP会显示可操作的选择框：高清分图、缩小为单张、仅本次改为高清PNG或取消。不需要重新收集回答；不再直接报错。缩小后的尺寸及文字变小影响会明确显示。

导出某一条回答（包含上面的问题）
- 点击该回答作者栏、关注按钮旁边的“导出此回答”。
- 导出问题标题、当前可见的问题描述和这条回答，不包含其他回答；无需改右下角数量。
- 在单条 /answer/ 详情页同样可用。该页面的批量入口禁用，批量请返回问题列表。
- 清晰度使用右下角面板选项。运行时可用面板“取消”停止。

说明
- “前 X 个”解释为提问下面的前 X 条回答；按页面当前实际展示顺序，不强制按赞同数重排。
- 使用页面可见内容，保留作者、回答链接、正文和图片；不包含评论、广告和投票操作栏。
- 这是对回答内容重排后生成的长图，不是原网页界面的逐像素截图。
- 不绕过登录、验证码或付费内容限制。可能受限的内容会在图中提示。
- 图片通过油猴从知乎 zhimg.com 图片域名读取，不发送回答内容到第三方服务。
- html2canvas 1.4.1 通过 @require 从 jsDelivr 加载；首次安装需要联网。
- 视频、音频及交互内容用提示文字代替。无法读取的图片也会标记，不会静默省略。
- 若不足 X 条，脚本会询问是否导出已收集的数量；不会把较少的结果标为 X 条。
- 1.2.0：默认 SCALE=2，以900像素排版宽度输出1800像素宽的PNG，不再因内容过长自动降低清晰度。
- 单张模式使用小块画布渲染，再逐行流式编码一个完整 PNG 文件；不创建整张大画布，因此输出高度可以超过30000像素，无需自动分图。
- 需要支持 CompressionStream 的现代桌面浏览器；不需要额外安装压缩库。
- 极长图的预览只显示顶部，下载按钮仍保存完整的一张图。某些浏览器、聊天平台或图片查看器不能解码超大图片，这是查看端限制；可使用支持大图的查看器，或选择备用“高清分图”。
- 默认压缩文件上限 MAX_FILE_MB=512MB，用于避免内存耗尽；这不是最终图片的像素高度限制。耗时随回答总长度和照片数量增加。
- EXPORT_MODE: 'single' 表示默认单张；改为 'split' 可默认高清分图。SCALE 可设置整数1～4；更高倍率不能恢复源照片本身缺失的细节。
- 拼接采用整数倍率直接复制像素，避免中间缩放插值。
- 预览默认适应窗口，可能看起来模糊；点击“100%像素查看”，或下载后在图片查看器用100%比例检查。
- 聊天软件发送超长图片可能再次压缩。需要保留清晰度时，请作为文件发送，或使用高清分图。
- “取消”会在当前图片请求或当前截图块处理结束后停止，图片请求超时为15秒。
- QUESTION_ID 留空用于所有问题；填入 2087509207285248045 可仅显示在指定提问页面。
- 首次使用建议 X=2，核对作者、顺序、正文末尾和图片后再增加数量。

验证范围

- 1.8.0在独立Edge进程的模拟知乎页面通过扩展加载、设置保存和读取、展开正文、两条回答导出、1800×3856 PNG下载解码及油猴核心真实渲染检查。

- 知乎可能修改页面 DOM；如果提示未找到回答，需要按当时页面结构调整选择器。
